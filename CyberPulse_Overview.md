# CYBER-PULSE — Project Overview

A physics-based **rhythm FPS**. You pick a music track; the game analyses it and
builds the arena, the enemy waves and the beat from that audio. Fighting *on the
beat* is the core mechanic — it rewards damage, resources and mobility. Built in
**Unity 6000.4.0f1 / URP 17**, all code under the `CyberPulse.*` namespaces.

This document is a standalone reference. Every section names the files/methods it
describes so you can jump straight to the code.

---

**Architecture conventions**
- **Managers are singletons** (`Instance`) — `GameManager`, `BeatClock`,
  `TraceMeter`, `SyncGauge`, `ScoreManager`, `LayerManager`, `WaveDirector`,
  `SongAnalyzer`, `AudioAnalyzer`, `TimeManager`, etc.
- **Systems talk through C# events**, not direct references, so they stay
  decoupled (e.g. `EnemyHealth.OnAnyEnemyKilled`, `BeatClock.OnBeat`,
  `WeaponBase.OnAnyWeaponFired`).
- **Input is a ScriptableObject** (`InputReader`) wrapping the generated
  `PlayerInputActions`, exposing events (`JumpInput`, `FirePressed`, …).
- **HUD is immediate-mode** (`OnGUI`), no Canvas — see `DiegeticHUD.cs`.
- **The playable scene is generated by an editor script** (`PlayableLevelBuilder`)
  rather than hand-placed, then interior geometry is generated *again* at runtime
  from the song (`ProceduralArenaGenerator`).

## 2. Gameplay loop & phases

`GameManager` (`Systems/GameLoop/GameManager.cs`) owns the phase state machine.
`GamePhase` = **Infiltrate → Siphon → Purge → Extract**. `SetPhase()` only ever
moves *forward* (`(int)phase <= (int)CurrentPhase` is rejected).

| Phase | Entered when | What happens |
|-------|--------------|--------------|
| **Infiltrate** | start | initial state before waves are ready |
| **Siphon** | `WaveDirector.ApplyProfile` after analysis | shoot **Data Nodes** to siphon them |
| **Purge** | all nodes siphoned (`DataNodeManager.OnNodeSiphoned`) | combat focus |
| **Extract** | all waves sent **and** 0 enemies left (`TraceMeter.OnEnemyKilled`) | "reach the exit" |

There are **two run structures**, decided by whether a `LayerManager` exists:

- **Single arena** — `WaveDirector.Update()` triggers the **win** when the song
  ends, all waves have spawned, and `TraceMeter.EnemyCount == 0`.
- **Layered (stacked floors)** — each floor is an `ArenaLayer`. Clear a floor
  (all its nodes siphoned + all its waves spawned + no enemies) → its
  `LockedDoor` unlocks → walk through → the door **re-locks behind you** and the
  next floor activates. Clearing the **top** floor (the one with no exit door)
  triggers the win. If the **song ends before** you reach the top, it's a **fail**.

**Fail** is driven by the TraceMeter reaching 100 (see below) →
`GameManager.TriggerFailState()`. Both win and fail show an overlay
(`GameOverlay.cs`) then reload the scene after a delay.

## 3. Resources

| Resource | Class | Range | Fills | Drains | Effect |
|----------|-------|-------|-------|--------|--------|
| **Trace** (the real "health") | `TraceMeter` | 0–100 | +1.5/s while enemies alive (×1→3 over song); +8 per player hit | −12 per kill; −3 per 500-score milestone; missile intercepts | 50 = alert music, 80 = critical post-FX, **100 = fail** |
| **SYNC** (special meter) | `SyncGauge` | 0–100 | on-beat shot +8, kill +25, dash +5 | off-rhythm −1/s; damage −10 | spend on weapon **special**; auto-fires special at 100 |
| **Score / Combo** | `ScoreManager` | — | 100 × combo per kill | combo resets after 5 s idle | combo ×1…×8; +1 same weapon, **+2 on weapon-swap kill** (variety bonus) |
| **Ammo** | per `WeaponBase` | mag + reserve (cap 300) | on-beat kill +6 reserve; pickups +12 | firing | empty mag auto-reloads |
| **HP** | `PlayerStats` | — | — | enemy damage | set to **9999** in the build, so the **TraceMeter is the true survival gate**, not HP |

Notable detail: `TraceMeter` passive fill is **paused for 4 beats after any
on-beat shot** (`_beatStopCountdown`) and the fill rate **ramps from ×1 to ×3
over the course of the song** (`SongProgress()`) — staying rhythmic buys time,
and pressure escalates as the track plays out.

## 4. The rhythm core

This is what makes it a *rhythm* shooter. Three classes cooperate:

- **`BeatClock`** (`Systems/Rhythm/BeatClock.cs`) — the metronome. It reads the
  song's playback position as `musicSource.timeSamples / AudioSettings.outputSampleRate`
  (sample-accurate, **drift-free**, unlike `Time.time`). From BPM it computes
  `BeatPhase` (0–1 within a beat) and `IsOnBeat` (true when phase is within
  `±_beatWindowSize`, default 0.15). Fires `OnBeat` on each beat crossing.
- **`BeatReactor`** (`Systems/Rhythm/BeatReactor.cs`) — turns on-beat actions
  into rewards, and off-beat play into penalties. Subscribes to weapon-fire,
  enemy-kill, dash and damage events and checks `BeatClock.IsOnBeat`.
- **`SyncGauge`** — the SYNC resource the reactor feeds.

**On-beat rewards / off-beat penalties** (the central "conditions"):

| Action on the beat | Reward | Code |
|--------------------|--------|------|
| Shot | +8 SYNC, **1.5× damage**, pauses Trace fill 4 beats | `BeatReactor.HandleWeaponFired`, `HitscanWeapon`/`RevolverWeapon` damage mult |
| Kill | +25 SYNC, **+6 reserve ammo** | `BeatReactor.HandleEnemyKilled` |
| Dash | +5 SYNC, **dash cooldown reset** | `BeatReactor.HandleDash` → `DashAbility.ResetCooldown` |
| Reload | **instant** (no reload time) | `WeaponBase.TryReload` |
| Weapon switch | **instant** (else 0.4 s delay) | `WeaponHolder.SwitchTo` |
| Shotgun blast | spread tightens to **40%** | `ShotgunWeapon.FireProjectile` |
| Double jump | jump force **×1.4** | `PlayerController` (`_onBeatDoubleJumpMultiplier`) |

**Off-rhythm** (no on-beat action for 2 s, `BeatReactor.Update`): move speed
**×0.7**, fire rate **×0.6**, SYNC drains 1/s. Taking damage costs 10 SYNC.

## 5. Song analysis (complex feature)

Two analysers run at different times for different purposes.

### 5a. Offline structural analysis — `SongAnalyzer.cs`
Runs once (coroutine `AnalyzeRoutine`) to extract the song's *structure*. Output
is a `SongProfile` struct (`SongProfile.cs`):
`{ BPM, BeatInterval, Duration, AverageEnergy, EnergyVariance, EnergyTimeline[], PeakEnergy }`.

Pipeline:
1. `clip.GetData` → mix all channels down to mono.
2. **Energy timeline**: split into 2048-sample windows, compute **RMS energy**
   per window.
3. **Onset detection**: a window is an onset if its energy exceeds a *dynamic*
   threshold (`max(_energyThreshold, avg × _onsetThreshFactor)`) and is a local
   maximum.
4. **BPM** (`DetectBPM`): build a histogram of inter-onset intervals → candidate
   BPMs (with octave-folding ×2), clamp 60–200, bias toward the 80–160 range,
   pick the most-voted bucket.
5. A coarse **0.5 s-bucket energy timeline** + its **variance** are stored — these
   drive generation later.

Has a **manual BPM override** and a **fallback profile** (120 BPM) if there's no
clip. Fires `OnAnalysisComplete(profile)`, which `BeatClock`, `WaveDirector` and
`ProceduralArenaGenerator` all listen to.

### 5b. Real-time spectral analysis — `AudioAnalyzer.cs`
Runs every frame off the live `AudioListener` for *visual/feel* reactivity:
- `Amplitude` = RMS of `GetOutputData` (overall loudness).
- `BassAmplitude` = FFT bins 1–5 (~85–430 Hz), `MidAmplitude` = bins 8–30.
- Smoothed with **fast attack / slow decay** so beats hit sharply but fade
  naturally.

This feeds `EnvironmentAudioReactor` (wall emissive pulsing, the global
`_CyberBeatPulse` shader value) and other visual systems.

## 6. Procedural generation from the song (complex feature)

Both the *terrain* and the *enemy waves* are derived from the `SongProfile`.

### 6a. Terrain — `ProceduralArenaGenerator.cs`
On `OnAnalysisComplete`, `Generate(variance, avgEnergy)` fills the arena interior:

- **Block count** = `Lerp(_minBlocks 10, _maxBlocks 28, EnergyVariance)` — busier
  songs → denser arenas.
- **Deterministic seed**: `Random.InitState(variance·1000 + avgEnergy·999 + seedOffset·7919)`.
  The same song always produces the **same layout**; stacked floors differ via
  `_seedOffset`.
- **6 archetypes** chosen by a variance-weighted roll (`PickArchetype`):
  Pillar, Wall, Cover, Bunker, **Platform**, **Tower**. Heights scale with
  `avgEnergy` (`GetDimensions`).
- **Placement constraints** (`TryPlaceBlock`, up to 40 attempts each): inside
  `_arenaHalf` 24, ≥ `_spawnClearance` 9 m from the spawn, ≥ `_centerClearance`
  4 m from center, ≥ `_minSpacing` 1.5 m apart (rectangle overlap test against
  `_occupied`).
- **Verticality**: Platforms/Towers are raised; their tops are pushed to
  `ElevatedAnchors` and get a cyan **`JumpPad`** at the base so they're reachable.
- Walls/Bunkers get a 35 % chance of an L-shaped **wing** (`TryPlaceWing`).
- Each block is a `Cube` named **"Cover"** with a `NavMeshObstacle`. **Only
  floor-level blocks carve** the NavMesh (`carveNavMesh = yBase < 0.5`); elevated
  platforms don't, so the floor underneath stays walkable.

Fires `OnArenaGenerated`, which triggers NavMesh baking and elevated data-node
relocation.

### 6b. Enemy waves — `ProceduralLevelGenerator.cs` + `WaveDirector.cs`
`ProceduralLevelGenerator.Generate(profile)` (a static utility) turns the energy
timeline into a `WaveDefinition[]`:

- **Spawn times** = energy-timeline **peaks** (`FindPeaks`): local maxima ≥ 60 %
  of peak energy, **≥ 8 s apart**, **≥ 5 s** into the song. Waves are capped to
  2–10 and any gap > 25 s gets a filler wave inserted — so combat tracks the
  song's intensity but never goes quiet too long.
- **Per-wave count** scales with `avgEnergy` + song progress (3–12 enemies).
- **Roster unlocks with progress** (`AvailableTypes`): Seeker + TriangleMirror
  from the start; **+CylinderLauncher at 20 %**; **+SphereAerial & CubeSplitter
  at 40 %**.
- **Spawn positions** are placed on a ring (radius 14–23) around the player.

`WaveDirector` (singleton) then spawns them at runtime:
- Compares song time to each wave's `SpawnTime` (drift-free `timeSamples`).
- In **layered** mode it splits waves across floors (`AssignWaveLayers`),
  **re-bases timing** to the moment you arrive on a floor (`HandleActiveLayerChanged`)
  so upper floors are always populated regardless of song clock, and **scales
  counts up per floor** (`×(1 + index × 0.33)` → roughly 1× / 1.33× / 1.67×).
- Resolves spawn positions against geometry: ground enemies snap to the NavMesh
  (`NavMesh.SamplePosition`), aerials keep height and jitter off obstacles.

## 7. Movement system — `Player/`

Physics-based FPS controller (`PlayerController.cs`,
`[RequireComponent(Rigidbody, CapsuleCollider)]`). All forces applied in
`FixedUpdate`: **UpdateGroundState → TryJump → ApplyMovement → ClampHorizontalSpeed
→ UpdateWallSlide → ApplyVariableGravity**.

| Feature | Field | Value | Notes |
|---------|-------|-------|-------|
| Move force | `_moveForce` | 140 | camera-relative `AddForce` |
| Max horizontal speed | `_maxHorizontalSpeed` | 18 | clamped, × `RhythmMultiplier` (off-beat 0.7) |
| Ground / air drag | `_groundDrag` / `_airDrag` | 12 / 0.5 | |
| Air strafe | `_airStrafeForce` | 45 | reduced air control |
| Jump | `_jumpForce` | 6.26 | |
| Double jump | `_maxJumps` | 2 | on-beat = ×1.4 force |
| Coyote time | `_coyoteTime` | 0.12 s | jump shortly after leaving ledge |
| Jump buffer | `_jumpBufferTime` | 0.15 s | press slightly before landing |
| Wall slide | `_maxWallSlideSpeed` | −2 | 4-direction SphereCast |
| Fall gravity | `_fallGravityMultiplier` | 1.4 | snappier falls |

Ground detection is a **SphereCast against `_groundLayer`**. Exposes
`IsGrounded`, `IsWallSliding`, `IsDashing`, `CurrentSpeed`, `OnLanded`.

- **Dash** (`DashAbility.cs`): camera-forward XZ impulse, `_dashForce` 40,
  `_cooldownDuration` 1.2 s, `_dashStateDuration` 0.2 s; on-beat dash resets the
  cooldown (via BeatReactor). Fires `OnDashPerformed`.
- **Camera** (`PlayerCamera.cs`, on a `CameraPivot` child): mouse look
  (sens 0.15, pitch ±80°), dynamic FOV (75 → 100 by speed), head-bob, dash
  kickback, landing dip, wall-slide tilt, `Shake(intensity, duration)`. Yaw
  rotates the body; pitch/roll are local to the pivot.

## 8. Weapons — `Weapons/`

`WeaponBase` (abstract) handles fire-rate gating, magazine/reserve ammo, reload
timing (instant on-beat), muzzle flash and audio. Subclasses implement
`FireProjectile()`. `WeaponHolder` forwards input, switches weapons (scroll +
number keys, instant on-beat else 0.4 s delayed), and routes the **special**.

| Weapon | Class | Damage | Fire | Ammo | On-beat | Special (`TriggerSpecial`) |
|--------|-------|--------|------|------|---------|----------------------------|
| **Revolver** | `RevolverWeapon` | 75 hitscan | slow, single | 6-round cylinder | ×1.5 dmg | **Ricochet** bullet: 80 dmg, 2 bounces, 3 m AoE (`Projectile`) |
| **SMG / rifle** | `HitscanWeapon` | 25 hitscan | automatic, looped audio | 30 mag | ×1.5 dmg | **Burst**: 6 shots @ 30/s |
| **Shotgun** | `ShotgunWeapon` | 8 pellets × 15 | pump, 2-round | wide 24° | spread → **40%** (9.6°) | **Knockdown blast**: 16 rays, knockback + player hop |

Mechanics:
- **On-beat damage** is read inside the weapon via `BeatClock.IsOnBeat`
  (`_onBeatDamageMultiplier 1.5`).
- **Specials** cost SYNC. Right-click (alt-fire) both **enters slow-mo**
  (`TimeManager.EnterSlowMo`) *and* spends `SpecialCost` SYNC to fire the special
  (`WeaponHolder.OnAltFirePressed` → `SyncGauge.TrySpend`). Separately, when SYNC
  hits **100** it auto-fires the special (`SyncGauge.OnSyncFull` →
  `WeaponHolder.OnSyncFull`).
- `RhythmFireMultiplier` (static) is dropped to 0.6 by BeatReactor while off-beat.
- `LastFiredWeaponSlotIndex` (static) lets `ScoreManager` award the swap-kill
  variety bonus.

## 9. Projectiles & collision detection

**Hitscan** (Revolver, SMG, Shotgun): `Physics.Raycast` from the camera against a
`_hitMask`. Before applying damage it checks for a `ShieldReflector` on the hit
collider (`TryDeflect`); otherwise it calls
`hit.collider.GetComponentInParent<IDamageable>()?.TakeDamage(...)`. A short
fading `LineRenderer` draws the tracer.

**`Projectile.cs`** (homing missiles, revolver ricochet, triangle shots):
Rigidbody-driven (`linearVelocity = forward × speed`, no gravity, continuous
collision). 
- `OnCollisionEnter` filters by `_hitMask` layer, then either does an
  `OverlapSphere` AoE (`_wallAoeRadius > 0`) or single-target damage, then
  destroys itself.
- **Homing**: `Vector3.RotateTowards` toward target each `FixedUpdate`
  (`SetHoming`). **Ricochet**: `Vector3.Reflect` off non-damageable surfaces
  (`SetRicochet`).
- It **implements `IDamageable`** — so the **player can shoot down incoming
  missiles**; `TakeDamage` fires the intercept callback (`SetInterceptReward` →
  TraceMeter drain + score) and destroys it.

**The universal damage contract** is **`IDamageable`** (`Combat/IDamageable.cs`):
`void TakeDamage(int)` + `bool IsDead`. Player (`PlayerStats`), every enemy
(`EnemyHealth`), data nodes (`DataNode`) and projectiles all implement it, so any
damage source works on any target without special-casing.

**Detection methods** in use: `Physics.Raycast` (hitscan, line-of-sight),
`Physics.OverlapSphere` (melee, AoE, sensors), `Physics.SphereCast` (ground/wall
checks), `Physics.CheckSphere` (placement validity), and **trigger volumes**
(jump pads, locked doors, ammo pickups, exit). Everything is gated by **physics
layers / LayerMasks** (`_playerLayer`, `_groundLayer`, `_obstacleMask`).

## 10. Enemies — `Enemy/`

Shared parts: **`EnemyHealth`** (HP, `IDamageable`, `OnDeath`, static
`OnAnyEnemyKilled`, 35 % chance to drop +12 ammo), **`EnemySensor`** (periodic
OverlapSphere range 15 m + 120° FOV + LOS raycast → `OnPlayerSpotted/Lost`),
**`EnemyDeathShards`** (death VFX), **`EnemyStateVisual`** (colour by state).
HP values below are set per-prefab in `PlayableLevelBuilder`.

| Enemy (`EnemyType`) | Class | HP | Move | Attack | NavMesh? |
|---------------------|-------|----|------|--------|----------|
| **Seeker** | `EnemyController` + `EnemyAttack` | 50 | NavMesh agent, patrol 2.5 / chase 5 | melee 10, 2.5 m, 1.5 s cd | **Yes** |
| **SphereAerial** | `EnemySphereAerial` | 80 | hovers y 5–7, drifts | charged **laser AoE**: 30 dmg, r 5, 2.5 s charge, 6 s cd | No (transform) |
| **TriangleMirror** | `EnemyTriangleMirror` | 60 | 65% player speed, 3 dashes / 4 s recharge | orange projectile 12 dmg @ 16 m/s | No |
| **CylinderLauncher** | `EnemyCylinderLauncher` | 70 | orbits player (r 10, 45°/s) | **homing missile** 20 dmg, AoE 2, every 3 s | No |
| **CubeSplitter** | `EnemyCubeSplitter` | 100 | slow seek (2 m/s) | melee 15, 1.8 m | No |

**Behaviour highlights**
- **Seeker** is the only NavMesh enemy — a classic FSM
  (`Idle→Patrol→Chase→Attack→Dead`, `EnemyController.cs`) reacting to sensor
  events. Safeguard in `Update`: if it's off the NavMesh or beyond radius 38
  (`EscapeRadius`) for > 1 s, it self-destructs so it can't get stuck.
- **SphereAerial** telegraphs its laser with an expanding **warning ring**
  (`AoEIndicator`); taking ≥ 40 % max HP during the 2.5 s charge **interrupts**
  it (`_interruptFraction`).
- **TriangleMirror** carries a **front shield** (`ShieldReflector`) that reflects
  hitscan back at half damage — but **only while it still has dash charges**.
  Counter-play: bait its 3 dashes, then punish during the 4 s recharge.
- **CubeSplitter** spawns **4 half-scale, faster, 1-HP melee cubes** on death
  (`SpawnSplits`); the small ones don't split again.
- **CylinderLauncher** missiles emit a **rising-rate proximity beep**
  (`MissileLockOn`, alert radius **10 m**, interval 0.30→0.08 s as it nears) and
  can be **shot out of the air** for a reward.
- **Knockback** (`KnockbackReceiver`) is added on demand by the shotgun special.

`EnemySpawner.cs` is a simpler timed/capped spawner kept for testing (Purge-phase
auto-spawn); the live game uses `WaveDirector`.

## 11. NavMesh — runtime, per-floor

Uses **Unity AI Navigation** (`NavMeshSurface`, one per `ArenaLayer`).

- The NavMesh is **baked at runtime**, *after* the procedural arena geometry
  exists: `ArenaLayer.BakeNavMesh` runs on
  `ProceduralArenaGenerator.OnArenaGenerated` (or immediately if already
  generated) and calls `_navSurface.BuildNavMesh()`.
- Procedural blocks add a **`NavMeshObstacle`**; **floor-level blocks carve**
  (`carveOnlyStationary`) so paths route around cover, while **elevated
  platforms/towers don't carve** so the floor beneath stays walkable.
- Only the **Seeker** uses a `NavMeshAgent` (height 2, radius 0.4, accel 12,
  angular 360). Other enemies move by transform and ignore the NavMesh entirely.
- `WaveDirector` snaps grounded spawns onto the mesh (`NavMesh.SamplePosition`,
  6 m search).
- `ArenaLayer.Update` **culls enemies that fall** below `floorY − 3`
  (`_fallCullDepth`) so a unit that clips off a floor can't block that floor from
  clearing.

## 12. Terrain — what's in the arena

| Element | Source | Role |
|---------|--------|------|
| Floor, outer walls, ramp, lighting, post-FX volumes, grid shader | `Editor/PlayableLevelBuilder.cs` (baked into the scene) | static shell of each arena |
| **Cover blocks** (Pillar/Wall/Cover/Bunker) | `ProceduralArenaGenerator` (runtime) | LOS breaks, chokepoints; NavMesh-carving |
| **Platforms / Towers** | `ProceduralArenaGenerator` | elevated surfaces → `ElevatedAnchors` |
| **Jump Pads** (`JumpPad.cs`) | placed at elevated-block bases | trigger volume; +15 upward impulse to reach platforms |
| **Data Nodes** (`DataNode.cs`) | placed by builder / per layer | shoot-to-siphon objective; `IDamageable`, one hit activates |
| **Locked Door** (`LockedDoor.cs`) | top of each ramp (layered mode) | red while sealed, green/open when the floor clears; re-seals after you pass |
| **Ammo Pickup** (`AmmoPickup.cs`) | enemy drops | +reserve ammo |
| **Data-bit particles** | `Systems/Visuals/DataBitRenderer.cs` | 1000 GPU-instanced cyan cubes; cluster on `ElevatedAnchors`, orbit & repel from the player — the "pulse" you see on platforms |

`DataNode` siphoning: one hit (`TakeDamage`) flips it from cyan to green, plays
VFX, fires `OnSiphoned`. Nodes self-register with `DataNodeManager` (single
arena) or belong to an `ArenaLayer` (layered). `DataNodeManager` relocates
**40 % of nodes onto platform/tower tops** (`RelocateToElevated`) to reward
vertical movement; `ArenaLayer.ResolveNodeOverlaps` nudges any node embedded in
geometry to a clear spot.

## 13. Layered progression — `LayerManager` + `ArenaLayer` + `LockedDoor`

- **`ArenaLayer`** (per floor) collects its nodes (revealing one per cleared
  wave, `RevealNextNode`), tracks live enemies, bakes its own NavMesh, and fires
  **`OnCleared`** when *all nodes siphoned + all waves spawned + 0 enemies*
  (`CheckCleared`).
- **`LayerManager`** owns the ordered floor stack (index 0 = ground). On
  `OnCleared` it **unlocks** that floor's exit door (or triggers the **win** if
  it's the top floor with no door). When you walk through the door
  (`LockedDoor.OnPlayerPassed`) it **re-locks** it and advances the active layer,
  firing `OnActiveLayerChanged` — which `WaveDirector` uses to re-base that
  floor's wave timing.

## 14. Audio-reactive visuals

- **`EnvironmentAudioReactor`** publishes a global shader float
  **`_CyberBeatPulse`** (a decaying 0–1 envelope from `AudioAnalyzer.BassAmplitude`)
  and lerps wall/ceiling emissive between a base and a peak colour. The grid-floor
  shader and walls read that value to pulse with the bass.
- **`DataBitRenderer`** draws the floating cyan bits (see Terrain table) — the
  platform "pulse" is these orbiting particle clusters, *not* an emissive glow.
- `TimeManager` drives slow-mo (alt-fire) and a hard **kill-cam freeze** (5 % time
  for 0.8 s) on the last-enemy kill, pitching down non-looping audio to match.
- Post-processing (Bloom/Tonemapping/Vignette/ChromaticAberration) lives in scene
  Volumes baked by `PlayableLevelBuilder`; the TraceMeter critical state and
  slow-mo blend their weights up at runtime.

## 15. Build pipeline note

The whole playable scene — player rig, weapons, the 5 enemy prefabs, lighting,
volumes, grid shader, HUD, data nodes, ramps/doors — is assembled by
**`Editor/PlayableLevelBuilder.cs`** (a ~1600-line editor baker), not placed by
hand. Runtime systems then layer the song-driven geometry and waves on top. A
practical consequence: shaders used only at runtime must be **pinned** (the
`Resources/M_URP_Unlit.mat` material, with GPU-instancing variants enabled) or
they get stripped from the build and particles/effects silently vanish in the
shipped player.

## 16. Key conditions cheat-sheet

- Phase only advances forward; **Siphon → Purge** needs every node;
  **Purge → Extract** needs all waves sent + 0 enemies.
- **Win**: song end + all waves + 0 enemies (single arena) **/** clear the top
  floor (layered). **Fail**: TraceMeter hits 100, or the song ends mid-climb
  (layered).
- Trace passive fill **only while enemies are alive**, **paused 4 beats** after an
  on-beat shot, and **ramps ×1→×3** across the song.
- **Off-rhythm after 2 s**: move ×0.7, fire ×0.6, SYNC drain. On-beat: damage
